# 操作とモード

KOGUMA.Mk3.1 の機体の操作、LED とブザーの合図、モードの割り当てをまとめたものです。

ToraNeko.Mk3 の `MODES.md`（ecd8e10）をもとにしました。2026-11-08 のアンケートで、作者が次のように決めました。

- 操作は ToraNeko の形：タイヤで選び、S2 で決定し、前センサに手をかざして離すとスタートする
- モードの並びは ToraNeko と同じ。探索（モード0）の No.1〜12 は KOGUMA.MkIIl と同じ
- 合図は LED とブザーで出す

中身は `sys/mode.c`・`sys/ui.c` です。KOGUMA.MkIIl との違いの細かいところは [KOGUMA_PORTING.md](KOGUMA_PORTING.md) にあります。

## 1. 使う部品

| 部品 | 使い方 |
|---|---|
| 左タイヤ | モードを選ぶ（KOGUMA.MkIIl と同じ） |
| 右タイヤ | No. を選ぶ（KOGUMA.MkIIl と同じ）。ゴールの x・y を入れる |
| スイッチ S2 | 決定。スタート待ちのときに押すと、選び直しに戻る。フェイルセーフで止まったときに押すと、元に戻る |
| 前センサ | 手をかざして、手を離すとスタート |
| 表示 LED 8 個（LED1〜8） | モードと No. の表示、合図 |
| 壁の表示の LED 4 個（LEDF1〜4） | センサの表示のモードで、壁の有無を出す |
| ブザー | 合図の音（KOGUMA.MkIIl と同じ高さ） |

## 2. 操作の流れ

1. 電源を入れる。「ロード中」（LED1→8 と 1 個ずつ点けて消す、1 秒）が出て、モード0 の No.0（何も選んでいない状態）になる。迷路は空で、ゴールは Flash から読む
   - 電池が少ないとき（15.6V より低い）は、外側の 4 個（LED1・2・7・8）が 0.5 秒ごとに点滅し、点くたびに低い音が鳴り続けて、何もできない。電池を替えて電源を入れ直す（電池を調べるのは電源を入れたときだけ。KOGUMA.MkIIl と同じ）
2. 左タイヤを回してモード、右タイヤを回して No. を選ぶ
   - 1 段ぶんにタイヤを回す量は KOGUMA.MkIIl と同じ（エンコーダ 300 カウント。`sys/ui.h` の `UI_TIRE_COUNT_PER_STEP`）
   - 前に回すと増え、後ろに回すと減る。モードは 7 の次が 0、No. は 15 の次が 0 に戻る（一周する。KOGUMA.MkIIl はモードも 0〜15）
3. スイッチを押して決定する。LED が 8 個全部 1 回点滅し、決定の音（ピッ）が鳴って、スタート待ちになる
   - 決定できるのは、中身のある番号だけ。No.0 や中身のない番号では、スイッチを押しても何も起きない
   - スタート待ちのあいだにスイッチを**短く**押して離すと、「ロード中」を出して 2 に戻る（間違えて決定しても、電源を切らずに済む）
   - スタート待ちのあいだにスイッチを **1 秒以上押し続ける**と、手をかざすかわりにスタートする。1 秒たつと 8 個全部が点き、スイッチを離すと消えて、1 秒後に走り出す。区画のまん中で前に壁があると、前センサは壁を見ていて、手をかざして離したのがわからないので、そのときに使う（壁合わせだけ（モード2 No.5）、センサ値の記録（モード5 No.2）など）
   - センサ値の表示（モード5 No.1）、壁までの距離の表示（No.3）、部品の確かめ（No.7）は、スタート待ちをせずにすぐ始まる。スイッチを押すと終わり、「ロード中」を出して 2 に戻る
4. 機体を置き、前センサに手をかざす。LED が 8 個全部点く
5. 手を離す。LED が全部消え、走り出す前の音（低い音 → 高い音。KOGUMA.MkIIl と同じ）が鳴って、1 秒後に走り出す
   - 走り出す処理は、はじめにジャイロの 0 点を測り直す（約 0.5 秒。手が触れた揺れがおさまってから測れる）
   - 手を離してから走り出すので、手を「前の壁」と読むことがない
6. 走り終わると、「うまくいった」の合図（8 個全部を 1 秒、はじめに短く高い音）を出し、「ロード中」を出してから、**同じモード・No. のまま** 2 に戻る（同じテストを続けて走らせやすい。KOGUMA.MkIIl はモード0 No.0 に戻っていた）
   - 持ち上げたときにタイヤが回って番号がずれることがあるので、スイッチを押す前に LED を確かめる
7. 2 に戻るときは、どこから戻るときも「ロード中」を出す（スタート待ちの取り消し、センサ値の表示の終わり、走り終わり、フェイルセーフの解除）。このあいだはスイッチを押しても何も起きないので、続けて押したスイッチが次の決定にならない

出力と設定（モード7）も、走るモードと同じ流れで始める（スイッチで決定 → 前センサに手をかざして離す）。

## 3. LED とブザーの表し方

モードは左の 4 個、No. は右の 4 個で、どちらも 2 進数で表す（KOGUMA.MkIIl と同じ表し方）。LED の並びは回路図・基板で確かめる。

```
左から（回路図・基板で確かめる）

   LED1  LED2  LED3  LED4      LED5  LED6  LED7  LED8
   └── モード（8・4・2・1）──┘  └─── No.（8・4・2・1）──┘

例：モード5 → LED2 と LED4 が点く（4 + 1）
    No.6   → LED6 と LED7 が点く（4 + 2）
モードは 0〜7 なので、LED1 はモードの表示では点かない
```

| 場面 | LED | 音 |
|---|---|---|
| 電源を入れたとき | 「ロード中」を出してから、モード0 No.0 の表示（全部消えている）になる | なし |
| 電池が少ないとき（電源を入れたときに調べる） | 外側の 4 個（LED1・2・7・8）を 0.5 秒ごとに点滅させ続ける。何もできない | 点いているあいだ、低い音（167Hz） |
| モードと No. を選んでいるとき | 選んでいるモードと No. を点けたまま | なし |
| スイッチで決定したとき | 8 個全部が 1 回点滅 | 決定の音（333Hz、0.3 秒。KOGUMA の Buzzer_Enter） |
| スタート待ち | 選んだモードと No. を点滅（選んでいるときと区別する） | なし |
| 前センサに手をかざしたとき | 8 個全部が点く | なし |
| 手を離したとき | 全部消える（1 秒後に走り出す） | 走り出す前の音（333Hz → 667Hz、0.4 秒ずつ。KOGUMA の Buzzer_Start） |
| 走り終わったとき | 「うまくいった」と同じ（8 個全部を 1 秒） | 短く高い音（2000Hz、0.1 秒） |
| Flash に保存しているあいだ（迷路・ゴール） | 外側の 4 個を点けておき、終わったら消す（約 1〜2 秒。CPU が止まるので、点けたままにしかできない。このあいだに電源を切ると保存が残らない） | なし |
| センサの表示（モード5 No.1・3・7） | 壁の有無を出す：左の壁 LED1・2、前の壁 LED3〜6、右の壁 LED7・8。壁の表示の LED にも出す（LEDF1 左前、LEDF2 右、LEDF3 左、LEDF4 右前。前の壁があると LEDF1・4 が点く） | なし |
| センサ値の記録で測っているあいだ（モード5 No.2。1 秒） | 真ん中の 4 個（LED3〜6）を点けたまま。終わったら「うまくいった」 | 終わったとき |
| 吸引 ON で吸っているあいだ（モード6 No.3） | 真ん中の 4 個（LED3〜6）を 0.5 秒ごとに点滅 | なし |
| フェイルセーフで止まったとき | 8 個全部を点滅させる。スイッチを押すと「ロード中」を出してから元に戻る | 止まったときに低い音を 0.5 秒 |
| ロード中 | LED1 から LED8 へ 1 個ずつ順に点けていき、8 個全部が点いたら消す（1 秒。KOGUMA.MkIIl の LED_Loading と同じ）。このあいだはスイッチを押しても何も起きない | なし |
| うまくいった（ゴールを保存した、迷路を呼び出せた、走り終わった、ログ出力が終わった） | 8 個全部を 1 秒点ける | 短く高い音 |
| できなかった（ゴールがスタートの区画を含む、保存した迷路がない、探索で道がなくなった、最短走行でゴールへの道がない） | 外側の 4 個を速く 5 回点滅させる | 点くたびに低い音（167Hz。KOGUMA の LED_Path_Error と同じ高さ） |

- 点滅の速さ：決定のときの全部の点滅は 0.15 秒ごと、スタート待ちの点滅は 0.25 秒ごと、フェイルセーフの全部の点滅・電池が少ないときの外側の点滅・吸引中の真ん中の点滅は 0.5 秒ごと、「できなかった」は 0.08 秒ごと、ロード中は 1 個 0.125 秒
- 音は、LED を点けている・待っているあいだに鳴らして止めるので、合図にかかる時間は ToraNeko.Mk3 と同じ
- 外側の 4 個だけの表示は 3 つあり、点き方と音で見分ける：点けたまま＝保存中、0.5 秒ごとに点滅し続けて低い音＝電池が少ない、速く 5 回点滅して低い音＝できなかった
- 入力の読み方：0.01 秒ごとに読む。スイッチは 2 回続けて同じ値を読んだら押した（離した）とみなす（チャタリングを取り除く）。前センサの手は 3 回続けて同じ値を読んだら、かざした（離した）とみなす
- モードを選び始めるときに、それまでにタイヤが回った量を忘れる（走っているあいだに回った量で、モードや No. が変わらないように）

## 4. モードの割り当て

| モード | 中身 | KOGUMA.MkIIl のモード |
|---|---|---|
| 0 | 探索 | モード0（No.1〜12 を同じ番号で） |
| 1 | 最短走行 | モード1、モード3 No.1〜3 |
| 2 | 探索のターン調整 | モード4 No.2・3・6 |
| 3 | 最短走行のターン調整 | モード5〜10、モード6 No.1〜7 |
| 4 | 実験用（加速度テストなど） | モード6 No.0 |
| 5 | センサ（値の表示と調整） | モード4 No.0、モード3 No.4〜9 |
| 6 | 基本調整 | モード4 No.1・4・5 |
| 7 | 出力と設定 | モード4 No.7（設定は KOGUMA にはない） |

**どのモードも No.0 は何もしない**（間違えて決定しても何も起きないように。電源を入れた直後はモード0 の No.0）。表にない番号も何もしない。

### モード0：探索

KOGUMA.MkIIl のモード0 と同じ 12 種類を、同じ番号で作る（2026-11-08 の作者の決定。中身は [KOGUMA_PORTING.md](KOGUMA_PORTING.md) の「モード0（探索）の 12 種類」）。中身は `sys/explore.c`。

| No. | 走り方 | 状態 |
|---|---|---|
| 1 | スラローム探索（吸引なし、500mm/s）往復 | 作った |
| 2 | スラローム探索＋エセ全面探索（行き止まり潰し） | 作った |
| 3 | スラローム探索 片道（ゴールで止まる） | 作った |
| 4 | 吸引探索（吸引 5.5V、1000mm/s）往復 | 作った |
| 5 | 吸引探索＋エセ全面探索 | 作った |
| 6 | 未知壁探索（吸引探索。ダイクストラ誘導） | 作った |
| 7 | No.6 ＋既知区間加速（見たことのある区画がまっすぐ 2 区画以上続くところを、最高 4000mm/s・15000mm/s² で） | 作った |
| 8 | No.1 → 続けて最短走行 | ステップ10 |
| 9 | No.4 → 続けて最短走行 | ステップ10 |
| 10 | No.7 → 続けて最短走行 | ステップ10 |
| 11 | No.10 の最短走行を 4 回（帰りも探索しながらスタートへ） | ステップ10 |
| 12 | No.10 の既知区間を斜めで走る | ステップ10 |

- 置き方：スタート区画に、お尻を後ろの壁に付けて北向きに置き、前センサに手をかざして離す。吸引探索は、手を離して音が鳴ったあと、吸引を 0.5 秒かけて上げ、0.5 秒待ってから走り出す
- 探索は、今 RAM にある迷路の続きから始める（KOGUMA.MkIIl と同じ）。最初からやり直したいときは、電源を入れ直す
- 終わり方：往復・エセ全面探索・未知壁探索はスタートの区画、片道はゴールの区画の**まん中**で止まる（後ろの壁に当てる動きはしない）。止まったら吸引を止め、迷路を Flash に保存して（外側の 4 個が点く）、「うまくいった」を出す
- エセ全面探索（No.2・5）：ゴールに着いたら、まだ入っていない区画を、いちばん近いものから順に見に行く。見た壁で袋小路とわかった区画は外す（行き止まり潰し）。見に行く区画がなくなるか、残りの区画にたどり着けなくなったら、スタートへ帰る
- 未知壁探索（No.6・7）：ゴールに着いたら、最短経路の上のまだ見ていない壁を見に行く。見に行く壁がなくなったら、止まらずにスタートへ帰る（ToraNeko.Mk3 と同じ流れ）。KOGUMA.MkIIl の「最短走行の値の組（2000・2400）ごとに経路の壁を見る」（B15）は、最短走行の値の組を作るステップ10 で足す
- 止まるのは、U ターン、未知壁探索で計算するとき、終わり。止まったところから発進するときは、前に壁があれば前壁合わせ（0.5 秒）をする
- 道がなくなったとき（壁の読み間違いなど）は、その場で止まって「できなかった」を出す。迷路は保存しない
- フェイルセーフで止まったときは、最後に壁を記録した 5 区画ぶんを戻してから迷路を保存し、8 個全部を点滅させる。S2 で戻る。スタートに置き直して同じ No. で走らせると、続きから探索する
- 横壁合わせ（`SIDE_ALIGN_ENABLE`）、前壁補正（`FRONT_CORRECTION_ENABLE`）、壁切れ（`WALL_EDGE_ENABLE`）は、今はどれも 0（測るだけ）。測った量は、ログ出力（モード7 No.1）の `#BEGIN RESULT` に出る
- KOGUMA.MkIIl は吸引探索の U ターンのあいだだけ吸引を弱めていた。それはまだ入れていない（実機で U ターンを見てから決める）

### モード2：探索のターン調整

探索で使う動きを 1 つずつ走らせて調整する。曲がるのは**左だけ**（KOGUMA.MkIIl と同じ）。中身は `sys/adjust.c`。どれも、走り終わった結果を覚えておき、ログ出力（モード7 No.1）で出す。

- **スラローム 90°（No.1）**：区画のまん中に置いて始める（左の区画をあけておく）。探索の動き（`ctrl/run.c`）そのままで、次の区画の入口まで 500mm/s に速くしながら進み、前距離 19.3mm → 左に 90°（最高 700deg/s、6366deg/s²）→ 後距離 19.5mm で左の区画の入口へ、そこから 90mm 進んで、左の区画のまん中で止まる。左を向いて止まっていれば合っている。合わなければ `config/run_params.h` の `SLALOM_PRE_MM`・`SLALOM_POST_MM` を直す
- **U ターン（No.2）**：区画のまん中に置き、前の区画が行き止まりになるようにして始める。前の区画のまん中で止まり、前壁合わせ（0.5 秒）→ 左に 90° → 前壁合わせ → 左に 90° と回って、元の区画のまん中まで戻って止まる
- **吸引探索のスラローム 90°（No.3）**：No.1 と同じ置き方。吸引を 5.5V まで上げて 0.5 秒待ってから、吸引探索の値（1000mm/s、最高 1640deg/s、前距離 32.3mm・後距離 32.5mm）で No.1 と同じ動きをする。止まったら吸引を止める。KOGUMA.MkIIl は前 15mm・後 50mm で、計算と違うので、ここで確かめる
- **その場 180° 旋回（No.4）**：左に 180° を、最高 600deg/s・角加速度 20000deg/s²（探索のその場旋回と同じ。KOGUMA.MkIIl の Motor_trapezoid_Turn(90, 600, 20000)）で回って止まる
- **壁合わせだけ（No.5）**：区画のまん中に、前に壁がある向きで置いて始める（前に壁があるので、スイッチの長押しで始める）。前の壁で位置と向きを 0.5 秒直して止まる

### モード4：実験用

- **加速度テスト（No.1・4〜12）**（`adjust_accel_test()`）：スタート区画に、お尻を後ろの壁に付けて置く。決めた加速度で速くなり、同じ加速度で遅くなって止まる。タイヤが滑り始める加速度を見つける
  - No.1〜11：4 区画目のまん中で止まる（564mm = 24 + 3 × 180）。速さの上限は決めず、半分まで速くして、残りの半分で止まる
  - No.1 は吸引なしで 8000mm/s²。No.4〜11 は吸引 5.5V で、8000・12000・16000・20000・25000・30000・35000・40000mm/s²
  - **No.12** は、KOGUMA.MkIIl のモード6 No.0 と同じ走り：吸引 8.1V で、40000mm/s² で 6000mm/s まで上げ、1080mm（6 区画）で止まる。スタート区画から 7 区画まっすぐの通路が要る
  - 走行ログ（1ms ごと）の `v`（エンコーダの速さ）と `acc_y`（IMU の前後の加速度）を見比べる。滑っていなければ `v` の傾きと `acc_y` が同じになる。止まった位置をものさしで測る

### モード5：センサ（値の表示と調整）

- **センサ値の表示（No.1）**：0.2 秒ごとに、壁センサ 4 つ（ON−OFF）、電池の電圧、角速度をシリアルに出す（KOGUMA.MkIIl のモード4 No.0 と同じ書式）。スイッチで終わる
- **センサ値の記録（No.2）**：区画のまん中に置いて始める。壁センサ 4 つを 1 秒測って、平均・いちばん小さい値・いちばん大きい値を覚え、ログ出力（モード7 No.1）で出す
- **壁までの距離の表示（No.3）**：0.2 秒ごとに、センサの値と壁までの距離 [mm] を `CAL,…` の形で出す（KOGUMA.MkIIl のモード3 No.4 と同じ書式）。スイッチで終わる
- **壁切れ・柱の見え方テスト（No.4〜6）**（`sys/edge_test.c`。KOGUMA.MkIIl のモード3 No.6〜8 と同じ考え方）：スタート区画に、お尻を後ろの壁に付けて置く。4 区画先の区画（(0,4)）のまん中まで、No.4 は 500mm/s（吸引なし）、No.5 は 1000mm/s、No.6 は 2000mm/s（No.5・6 は吸引 11.1V）で、20000mm/s² で速くして走って止まる。横のセンサの値を走行ログに細かく残す（No.4 は 2ms ごと、No.5・6 は 1ms ごと）。壁の並べ方は `sys/edge_test.c` の先頭のコメント。結果はログ出力（モード7 No.1）の走行ログ（`sensor_L`・`sensor_R`）と `#BEGIN RESULT` の `edge` の行。これで壁切れ（`ctrl/side_edge.c`）の値を決める。KOGUMA.MkIIl の No.9（2400mm/s）は、番号が足りないので入れていない
- **部品の確かめ（No.7。KOGUMA.Mk3.1 で足した）**：1 秒ごとに、制御周期の記録・エンコーダ・IMU・電池と壁センサ・壁までの距離の 5 行を出す（ステップ1〜7 の確かめで app.c が出していたもの。確かめ方は [README.md](README.md) の「確かめ方」）。スイッチで終わる
- **吸引のときのセンサのノイズ（No.8。KOGUMA.MkIIl のモード3 No.10。B7）**（`sys/sensor_noise.c`）：区画のまん中に置いて始める（前に壁があれば、スイッチの長押しで始める）。機体は動かない。吸引を 0・5.5・7.9・11.1V（KOGUMA の duty 0・35・50・70）の 4 段に変えながら、それぞれ 0.5 秒待ってから 1ms ごとに 500 回、受光 4 つの点灯・消灯・差を読み、平均・ばらつき・最小・最大を出す（約 5 秒。測っているあいだは真ん中の 4 個が点く）。`#BEGIN NOISE` の形は KOGUMA.MkIIl と同じで、ビューアの「センサのノイズ」で表になる。ケーブルを挿さずに測ったときは、ログ出力（モード7 No.1）で出る。吸引 0V のときより差のばらつきが大きくなるセンサがあれば、吸引で壁の読みが揺れている（KOGUMA.MkIIl は左前・左が揺れていた）

### モード6：基本調整

- **直進（No.1）**：スタート区画に、お尻を後ろの壁に付けて置く。564mm（4 区画目のまん中まで）を、最高 500mm/s・2000mm/s² で走って止まる。止まったら、後ろの壁からお尻までをものさしで測る。ログ出力の `Straight: … encoder …` と比べて、タイヤの直径（`config/robot_params.h` の `TIRE_DIAMETER_MM`）を直す（新しい直径 = 今の直径 × ものさしの距離 ÷ encoder の距離）
- **モーターの向きの確かめ（No.2。KOGUMA.Mk3.1 で足した）**：**タイヤを浮かせて**置き、前センサに手をかざして始める。左右のモーターに 1.0V を 2 秒かけて止める（制御はしない）。左右とも、機体が前に進む向きに回るかを見る。0.5 秒ごとに `MOTOR enc L=… R=…`（回り始めてからのエンコーダの量）を出す。前に回っていれば、L も R も増える
- **エンコーダの歪みを測る（No.6）**（`sys/encoder_cal.c`。ToraNeko.Mk3 と同じ）：**タイヤを浮かせて**から、前センサに手をかざして始める。左は前、右は後ろの向きに 1.0V で約 1.5 秒回して止め、`config/encoder_correction.h` に貼る表をシリアルに出す。今の表で直したあとに残るずれも出す（表を入れたあと、もう一度測ると、どれだけ効いているかがわかる）。1 回転の記録が足りない・多すぎると出たら、`CAL_VOLTAGE_V` を変える
- **吸引 ON（No.3）**：吸引を 5.5V まで上げ、スイッチを押すまで吸い続ける（機体は動かない）。0.5 秒ごとに `SUCTION_GYRO,時間[s],角度[deg]` を出す（吸っているあいだに、ジャイロがどれだけ流れるか）
- **壁に沿って直進（No.7）**：左右に壁がある通路に、少し左か右に寄せて（または少し斜めに）置いて始める。564mm を 500mm/s で、横の壁に沿って走る補正を入れて走って止まる。まん中に戻りながら走れば合っている。走行ログの `wall_err`・`wall_p`・`wall_d` で `config/ctrl_gains.h` の `WALL_KP`・`WALL_KD` を合わせる

### モード7：出力と設定

| No. | 中身 |
|---|---|
| 1 | ログ出力：最後に走らせた調整の動きの結果、センサ値の記録、センサのノイズ、RAM に残っている迷路・走行ログを PC へ出す（KOGUMA.MkIIl と同じ形。ビューア `tools/viewer.html` で保存して見る。残し方は [logs/README.md](logs/README.md)） |
| 2 | ゴールの位置（x・y）を入れる |
| 15 | 迷路呼び出し（Flash に保存した迷路を RAM に戻す） |

- モード7 は、モード0 から左タイヤを 1 段戻すと選べる。No.15 は、No.0 から右タイヤを 1 段戻すと選べる

**ゴールの入れ方**（No.2）

ゴールは「左下の区画の位置（x・y）」だけを機体で入れる。大きさは **2×2 で決まり**（`sys/goal.h` の定数）。

1. 8 個全部が 1 回点滅して（決定の音）、x の入力になる
2. 右タイヤを回して値を選ぶ。1 段で 1 ずつ変わる。最初は今のゴールの値
   - 値は LED5〜8 の 2 進数（LED5 = 8、LED6 = 4、LED7 = 2、LED8 = 1。No. と同じ場所）。LED1〜4 は消える
   - 入れられるのは 0〜14（2×2 のゴールが 16×16 の迷路からはみ出さないように）
3. スイッチを押す。8 個全部が 2 回点滅して、y の入力になる。y も 2 と同じように選ぶ
4. スイッチを押すと、Flash に保存して「うまくいった」を出す
   - x と y がどちらも 0 のときは、ゴールがスタートの区画を含むので保存せず、「できなかった」を出して x の入力に戻る

- ゴールは、電源を入れたときに Flash から自動で読む
- 一度も設定していない（Flash にゴールがない）ときは、迷路の中央の (7, 7)

## 5. 迷路の保存と呼び出し

KOGUMA.MkIIl は迷路を RAM にしか持たなかった（電源を切ると消える）。KOGUMA.Mk3.1 は ToraNeko.Mk3 と同じく、Flash にも保存する。

| 場面 | 迷路 |
|---|---|
| 電源を入れたとき | 空。Flash の迷路は自動では読まない |
| モード7 No.15（迷路呼び出し） | Flash の迷路を RAM に戻す（電池を替えたあとに、続きから最短走行・探索をするとき） |
| 探索を始めるとき | RAM の迷路の続きから |
| Flash に保存するとき | 探索でスタートに戻ったとき、片道でゴールに止まったとき、フェイルセーフで止まったとき（最後に壁を記録した 5 回ぶんを戻してから。探索を作るステップ9 で） |

**保存のしかた**（`sys/flash.c`、`drv/flash_memory.c`。ToraNeko.Mk3 と同じ）

| 項目 | 内容 |
|---|---|
| 保存場所 | Flash のいちばん後ろの 2 つのセクタ（128KB ずつ）。ゴールはセクタ6（0x08040000〜）、迷路はセクタ7（0x08060000〜）。STM32F446RE も STM32F411 と同じ区切り |
| プログラムの大きさ | 保存場所と重ならないように、前の 256KB（セクタ0〜5）に収める（2026-11-08 で約 90KB）。超えたら CI（firmware-build の「サイズ」）が失敗にする |
| 書く中身 | ゴール：目印、x、y、確かめの数（4 語）。迷路：目印、迷路の大きさ、区画ごとに 4 枚の壁の状態と「入ったか」、確かめの数（1283 語、約 5KB） |
| 壊れていないかの確かめ | 「目印」で保存したことがあるかを、「確かめの数」（それまでに書いた数の合計）で途中で電源が切れていないかを調べる。どちらかが合わなければ読まない |
| プログラムを書き込み直したとき | ふつうに書き込むと、プログラムが入るセクタだけが消されるので、保存した迷路とゴールは残る。書き込みツールで「全部消す（Full chip erase）」をすると消える |

- Flash を消しているあいだ（約 1〜2 秒）は CPU が止まるので、保存はモーターを止めているときだけにする
- **KOGUMA.MkIIl の大会用のプログラムと入れ替えるとき**：KOGUMA.MkIIl は Flash に書かない（`Core/` に Flash を消す・書く処理がない）。ふつうに書き込めばプログラムの入るセクタだけが消えるので、KOGUMA.Mk3.1 に戻したときに、保存した迷路とゴールは残っているはず（実機で確かめる）
